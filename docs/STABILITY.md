# Stability and version policy

What a version number means here, what 2.x keeps frozen, what a 3.0 may change, and how to pin a build.
Written against the `v2` branch as released (tag `2.0.0`); citations are paths plus line numbers, so they survive a commit but not an edit.

Status of the tree this describes: **2.0.0 is the version in the source, and the line has never been
released.** [`CMakeLists.txt:2-5`](../CMakeLists.txt#L2-L5) says so in as many words ("this branch has never
been released, so the number is the contract for its first release"). There is no git tag (`git tag` prints
nothing); [`CHANGELOG.md`](../CHANGELOG.md) exists and its top entry reads `## [2.0.0] - 2026-10-31`.

Companion documents: [`CONTRACT.md`](CONTRACT.md) (what callers may rely on), [`DECISIONS.md`](DECISIONS.md)
(why), [`V1_DIFFERENCES.md`](V1_DIFFERENCES.md) (what changed from v1).

## 1. Where the version lives

One authority, and projections of it:

- **Authority:** `project(cpp-kana2 VERSION 2.0.0)` ([`CMakeLists.txt:6`](../CMakeLists.txt#L6)). Every other
  manifest points here ([`CMakeLists.txt:3-5`](../CMakeLists.txt#L3-L5)).
- **Compile time:** `CPP_KANA2_VERSION_MAJOR/MINOR/PATCH/STRING` in
  [`Version.h`](../include/cpp-kana2/core/Version.h), written once by hand rather than generated — the header
  explains why a `configure_file()` header would need an extra install rule and gate exemptions
  ([`Version.h:4-14`](../include/cpp-kana2/core/Version.h#L4-L14)). `CPP_KANA2_VERSION_AT_LEAST(2, 1, 0)`
  gives an integer comparison in a `#if` ([`Version.h:24-29`](../include/cpp-kana2/core/Version.h#L24-L29)).
- **Run time:** `cpp_kana::v2::version()` and `cppk2_version()` both return `CPP_KANA2_VERSION_STRING`
  ([`Convert.cpp:143`](../src/core/Convert.cpp#L143); [`c_api.cpp:115-117`](../src/c_api/c_api.cpp#L115-L117)).
- **Package managers:** `cpp-kana2.pc` `Version:` ([`cpp-kana2.pc.in`](../cpp-kana2.pc.in)); Python
  `cpp-kana2` with `__version__` in `_version.py`, generated by
  [`python/tools/build_native.py`](../python/tools/build_native.py); C# `PackageId`/`Version` in
  [`version.props`](../csharp/CppKana2/version.props), generated by
  [`csharp/tools/emit_build_info.py`](../csharp/tools/emit_build_info.py).
- **CHANGELOG:** the top heading of [`CHANGELOG.md`](../CHANGELOG.md) — currently `## [2.0.0] - 2026-10-31` —
  compared with the authority like any other projection. The gate tolerates a *missing* file ("a fresh clone
  has never run the binding builds, and 'missing' is not drift") but not a heading that disagrees
  ([`check_version_tokens.py:8-9`](../tools/check_version_tokens.py#L8-L9),
  [`:83-88`](../tools/check_version_tokens.py#L83-L88)).

`tools/check_version_tokens.py` compares the authority with `Version.h`, `_version.py`, `version.props` and the
`CHANGELOG` heading, and names which projection disagrees.

## 2. What 2.x keeps frozen

1. **The public surface** — the three lists in [`tests/abi/`](../tests/abi/): the installed headers, the C entry
   points, the namespace-level names. Change requires `python tools/check_public_surface.py --freeze` and a
   review of that diff ([`CONTRACT.md` §1](CONTRACT.md)).
2. **Status values 0..7** — no renumbering, no re-meaning; the list may only be extended by appending
   ([`Types.h:19-22`](../include/cpp-kana2/core/Types.h#L19-L22)).
3. **Library-filled structures** — `cppk2_mora`, `cppk2_conversion`, `cppk2_error` gain no member inside 2.x
   ([`c_api.h:19-23`](../include/cpp-kana2/ext/c_api.h#L19-L23)).
4. **Package identity** — `<cpp-kana2/...>`, `cpp_kana::v2`, `cppk2_*`, CMake package `cpp-kana2`
   ([`DECISIONS.md`](DECISIONS.md) D2).
5. **The package-compatibility rule** — `SameMajorVersion`: a request inside 2.x is satisfiable by any 2.x
   install, a cross-major request is refused ([`CMakeLists.txt:309-318`](../CMakeLists.txt#L309-L318), asserted
   by `Gate_InstallConsumer`).
6. **The ELF SONAME** — `libcpp-kana2.so.2`, derived from the major version, so a bump moves it and nothing
   else needs to ([`CMakeLists.txt:126-135`](../CMakeLists.txt#L126-L135)).
7. **C++17 and zero third-party dependencies** — required through the exported target
   ([`CMakeLists.txt:247`](../CMakeLists.txt#L247)); the CI file states the position
   ([`.github/workflows/ci.yml:7-8`](../.github/workflows/ci.yml#L7-L8)).

**What is *not* frozen is the rendered output across releases.** 2.x freezes the surface; the fixture pins the
bytes that surface produces *today*, and a minor release may re-pin it for an intended behaviour fix — the diff
is the review. The fixture's own words: "re-pin after an intended change"; a change nobody re-pinned fails
`ConformanceFixture` instead of quietly rewriting the lock
([`conformance/README.md:17-28`](../conformance/README.md#L17-L28)).

## 3. What a 3.0 may change

Only what the repository's own rules set aside for a 3.0 — this section does not invent a scope:

- **New members in the library-filled structures.** Explicitly deferred: "A new field waits for 3.0 or arrives
  through a new function" ([`c_api.h:19-23`](../include/cpp-kana2/ext/c_api.h#L19-L23)).
- **Anything on the three frozen lists**, including removals and renames, through a deliberate `--freeze`
  ([`check_public_surface.py:10-13`](../tools/check_public_surface.py#L10-L13)).
- **The status value set** — the append-only rule is scoped to 2.x
  ([`c_api.h:51-53`](../include/cpp-kana2/ext/c_api.h#L51-L53)).
- **The SONAME and the package major**, which move together
  ([`CMakeLists.txt:126-135`](../CMakeLists.txt#L126-L135)).
- **A romanisation-scheme dimension**, if it is ever wanted: the plan records that scheme switching would be an
  *additive* change (a new enum value plus a new function) and is out of 2.0's scope
  ([`plans/cpp-kana2-v2-refactor.md` §1](plans/cpp-kana2-v2-refactor.md)).

Everything else a 3.0 might do is a decision that would have to be recorded in [`DECISIONS.md`](DECISIONS.md)
first; nothing in this tree implies it.

## 4. Deprecation

**No deprecation mechanism exists in 2.x, because the surface is frozen.** That is a statement about this tree,
and it is verifiable: outside this section, the string `deprecat` does not appear in `include/`, `src/`,
`tools/`, `tests/`, `python/`, `csharp/` or the build files; there is no `CPP_KANA2_DEPRECATED` macro alongside
`CPP_KANA2_EXPORT`/`CPP_KANA2_NODISCARD` in [`Global.h`](../include/cpp-kana2/core/Global.h); and no gate has a
deprecation allowance. The plan does not describe a deprecation policy either.

The consequence for a caller: there is no "marked deprecated but still present" phase in 2.x. An API is either
on the frozen lists — and then it stays as it is for the whole 2.x line — or the change is a 3.0 event. If a
deprecation mechanism is ever added, it is a new decision for the ledger (§3), not something to infer from the
current headers.

## 5. How to pin

Pick the axis that matters and pin that:

- **A source revision.** Branch `v2` has no tags today (`git tag` is empty), so pinning means a commit id. The
  conformance fixture records the commit that produced it (`generated_by_commit`), and
  [`tools/check_conformance.py:53-62`](../tools/check_conformance.py#L53-L62) fails when that field names
  something that is not a commit in the repository; `"unknown"` is a note, not a pass.
- **A package version.** `2.0.0` in CMake, the `.pc` file, the Python distribution and the C# package (§1). A
  consumer asks for it with `find_package(cpp-kana2 2.0 CONFIG REQUIRED)`; a request for `3.0` must be —
  and is — refused ([`tests/install/check_install_consumer.cmake:132-146`](../tests/install/check_install_consumer.cmake#L132-L146)).
- **A compile-time floor.** `#if CPP_KANA2_VERSION_AT_LEAST(2, 0, 0)`
  ([`Version.h:24-29`](../include/cpp-kana2/core/Version.h#L24-L29)).
- **A run-time fact.** Compare `cppk2_version()` against the string your build recorded — the Python suite's
  `test_version_chain` and the C# suite's "version chain" check do exactly that
  ([`csharp/CppKana2.Tests/Program.cs:56-64`](../csharp/CppKana2.Tests/Program.cs#L56-L64)).
- **The behaviour.** `conformance/cases.sha256` (value in §0). Re-pinning is two deliberate commands: regenerate
  with `cpp-kana2-conformance --write`, then `python tools/check_conformance.py --write`
  ([`conformance/README.md:17-23`](../conformance/README.md#L17-L23),
  [`check_conformance.py:106-122`](../tools/check_conformance.py#L106-L122)). Line endings are pinned to LF for
  the fixture and its digest by [`.gitattributes`](../.gitattributes), so the digest survives a Windows checkout.

## 6. What a version number does not promise

- **Binary compatibility.** "The package promises API compatibility inside a major version and never binary
  compatibility" ([`CMakeLists.txt:309-311`](../CMakeLists.txt#L309-L311)); the SONAME paragraph says the same
  thing again ([`CMakeLists.txt:126-130`](../CMakeLists.txt#L126-L130)). Rebuild when the library is replaced.
- **Byte-identical rebuilds.** Reproducibility flags are set for all four toolchains
  ([`CMakeLists.txt:45-84`](../CMakeLists.txt#L45-L84)), but no gate compares two builds, so this is a build
  setting, not a promise.
- **A release schedule or a support window.** Nothing in the repository states dates, an LTS policy, or how
  long a line is supported.
- **Platforms beyond what CI runs.** The CI matrix is `linux-gcc`, `linux-clang`, `linux-sanitize`,
  `linux-static`, `windows-msvc`, `windows-mingw`, `python`, `csharp`
  ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)). macOS is not among them, although the plan's G4
  lists it; `Gate_SonameGate` runs on ELF only, so on this project's Windows development machines that check is
  skipped, not passed.

## 7. How to check a pin

```bash
cmake --preset default && cmake --build --preset default && ctest --preset default
python tools/run_all_gates.py
```

`ctest` registers the gate scripts as `Gate_*` tests plus the three CMake gates (`ExportGate`, `SonameGate`,
`InstallConsumer`) and `ConformanceFixture`; `run_all_gates.py` runs every Python gate's self-test first and then
the gate itself, and returns one exit code
([`tests/CMakeLists.txt:63-148`](../tests/CMakeLists.txt#L63-L148),
[`run_all_gates.py:1-11`](../tools/run_all_gates.py#L1-L11)). The Python and C# suites are run by their own
runners ([`python/tests`](../python/tests), [`csharp/tools/run_tests.py`](../csharp/tools/run_tests.py)), and CI
runs both.
